# 출발 전 제안: 원화 환산, 환전 시점 안내, 교통권·패스·입장권·할인권 추천

여비와 예산 옆에 원화 환산이 참고로 붙고, 출발 14일 전부터 서비스가 "환전 할까요?", "교통패스 찾아볼까요?", "공항 교통권 찾아볼까요?", "입장권 찾아볼까요?", "할인권 찾아볼까요?"를 제안 섬으로 먼저 묻는다. 환율 안내는 수치 옆에 부드러운 한 줄 판단만 붙이고, 교통권·패스·입장권·할인권 추천은 확인을 누르면 마이리얼트립의 검색 결과로 넘긴다. 마이리얼트립 링크는 이 추천에만 쓰고 환율·환전과는 연결하지 않는다. 서비스 안에서 사거나 환전하지 않는다. [osaka-trip-budget](../osaka-trip-budget/spec.md)이 미룬 "원화 환산", [osaka-first-trip-loop](../osaka-first-trip-loop/spec.md)이 미룬 "환율 조회", `PRODUCT.md`의 "환율을 확인하고 구매 시점을 알려 준다"를 해소한다.

연결된 근거:
- [PRODUCT.md](../../../PRODUCT.md) — 제품 전제. 이 작업에는 "모든 제안은 사용자가 확인해야 실행된다", "직접 구매하지 않는다, 사기를 권하는 알림만 띄우고 확인을 누르면 마이리얼트립 웹이나 앱의 해당 검색어 결과로 넘긴다", "무겁지 않게, 필요한 순간에 필요한 것만"이 적용된다.
- [suggestion-nudge](../../decisions/suggestion-nudge.md) — 모든 제안은 노선도 아래 섬으로 보이고, 한 번에 하나, 처리하면 같은 상황에서 다시 뜨지 않는다. 이 스펙은 그 규칙을 다시 적지 않는다.
- [llm-integration](../../decisions/llm-integration.md) — 환율 안내와 구매 제안 문구는 LLM이 아니라 규칙과 API 수치로 만든다.
- [osaka-contextual-suggestions](../osaka-contextual-suggestions/spec.md) — 제안 섬과 처리 기록 방식, 개발 서버의 시각 흉내를 그대로 쓴다.
- [trip-documents](../trip-documents/spec.md) — 입장권 서류 칸에 파일이 있으면 그 장소의 입장권 구매 제안은 뜨지 않는다.
- [ui-composition](../../decisions/ui-composition.md) — 환산 표시와 섬 내용은 공식 shadcn 구성을 쓴다. 화면 작업은 `DESIGN.md`부터 읽는다.
- [GLOSSARY.md](../../../GLOSSARY.md) — 제안, 체크리스트, 예산, 여비, 서류 칸의 뜻. 이 작업이 환율 제안, 구매 제안, 기준환율을 더한다.

## 사용자에게 보이는 결과

1. 여비 기록, 일차 합계, 하루 권장액, 예산 카드의 금액 옆에 `≈ 11,500원`처럼 오늘 기준환율로 환산한 원화가 작고 옅게 보인다. 기록과 계산의 기준은 엔이고, 입력은 엔으로만 한다.
2. 출발 14일 전부터 출발 전날까지, 체크리스트의 "환전"이 미완료이면 환율 제안 섬이 뜬다. 펼치면 "지금 100엔 = 836원이에요"와 최근 30일 평균과의 차이, 그에 맞는 한 줄 판단, "참고용이에요. 환전은 은행이나 앱에서 직접 해 주세요."가 보인다.
3. 같은 기간에 체크리스트의 "교통패스"가 미완료이면 "교통패스는 미리 사 두면 편해요. 찾아볼까요?" 섬이 뜬다. 펼쳐서 확인을 누르면 마이리얼트립에서 "오사카 교통패스" 검색 결과가 새 탭으로 열린다.
4. 같은 기간에 "공항 교통권 찾아볼까요?" 섬이 한 번 뜬다. 확인을 누르면 마이리얼트립에서 "오사카 공항 교통권" 검색 결과가 새 탭으로 열린다.
5. 같은 기간에 코스에 입장권이 필요한 장소가 있고 입장권 서류 칸에 그 장소의 파일이 없으면 "유니버설 스튜디오 재팬 입장권 찾아볼까요?" 섬이 뜬다. 확인을 누르면 마이리얼트립에서 "유니버설 스튜디오 재팬 입장권" 검색 결과가 새 탭으로 열린다.
6. 같은 기간에 "여행 전에 할인권 챙겨 볼까요?" 섬이 한 번 뜬다. 확인을 누르면 마이리얼트립에서 "오사카 할인 쿠폰" 검색 결과가 새 탭으로 열린다.
7. "나중에"를 누르면 그날은 같은 제안이 다시 뜨지 않고 다음 날 다시 뜬다. 확인을 눌러 열었으면 그 제안은 끝난다.

## 승인된 범위

- 여비, 하루 합계, 하루 권장액, 예산 카드의 원화 참고 표시
- 환율 제안(출발 14일 전부터, 환전 미완료일 때)과 부드러운 판단 문구
- 교통패스, 공항 교통권, 입장권, 할인권 추천과 마이리얼트립 검색 링크
- 환율 API 실패 시의 조용한 생략

## 수용 기준

모두 실행 중인 앱에서 실제 브라우저로 확인한다. 시각은 개발 서버의 시각 흉내(`/dev/sim`)로 맞추고, 환율 실패는 `fx=fail` 흉내로 만든다.

- AC1. 여비를 1,280엔으로 기록하면 그 줄 옆에 오늘 기준환율로 환산한 원화(1엔 × 환율, 원 단위 반올림)가 `≈ 10,700원` 모양으로 보이고, 일차 합계, 하루 권장액, 예산 카드의 총예산·쓴 돈·남은 돈 옆에도 환산이 보인다. 입력 칸에는 원화 입력이 없다. 새로고침해도 엔 기록은 그대로이고 원화 값은 그날 환율을 따른다.
- AC2. 출발 14일 전(예: 출발 11-25의 11-11)에 체크리스트의 "환전"이 미완료이면 환율 제안 섬이 뜬다. 13일 전 이전에는 뜨지 않고, 출발 당일 이후에도 뜨지 않으며, "환전"이 완료이면 뜨지 않는다.
- AC3. 환율 제안을 펼치면 현재 100엔 환산액, 최근 30일 평균과의 차이(%), 판단 한 줄, 참고 안내가 보인다. 평균보다 2% 이상 낮으면 "평소보다 낮아서 환전하기 괜찮은 편이에요", ±2% 안이면 "평소와 비슷해요", 2% 이상 높으면 "평소보다 조금 비싸요. 급하지 않으면 며칠 지켜봐도 돼요"가 보인다. 환전 화면이나 환전하기 버튼은 없다.
- AC4. 환율 API가 실패하는 상황(`fx=fail`)에서는 원화 환산 표시와 환율 제안만 사라지고, 다른 모든 화면과 제안은 오류 없이 동작한다.
- AC5. 출발 14일 전부터 출발 전날까지 체크리스트의 "교통패스"가 미완료이면 교통패스 제안 섬이 뜨고, 확인을 누르면 `https://www.myrealtrip.com/search?query=오사카+교통패스`(주소 형태)로 새 탭이 열린다. "교통패스"가 완료이면 뜨지 않는다.
- AC6. 코스에 입장권이 필요한 장소(유니버설 스튜디오 재팬, 오사카성 천수각, 우메다 공중정원 전망대, 아베노 하루카스 300, 가이유칸 수족관, 덴포잔 대관람차, 신세카이 · 츠텐카쿠)가 있으면 장소마다 입장권 구매 제안이 뜨고, 확인을 누르면 "<장소 이름> 입장권" 검색 결과가 새 탭으로 열린다. 입장권 서류 칸에 그 장소에 연결된 파일이 있으면 그 장소의 제안은 뜨지 않는다. 코스에 해당 장소가 없으면 입장권 제안이 뜨지 않는다.
- AC6-1. 출발 14일 전부터 출발 전날까지 공항 교통권 제안과 할인권 제안이 각각 한 번씩 뜬다. 확인을 누르면 각각 "오사카 공항 교통권", "오사카 할인 쿠폰" 검색 결과가 새 탭으로 열리고, 그 제안은 끝난다. 둘 다 서류 칸이나 체크리스트에는 영향을 주지 않는다.
- AC7. "나중에"를 누르면 같은 제안은 그날 다시 뜨지 않고, 날짜를 하루 넘기면 다시 뜬다. 확인을 눌러 검색 결과를 연 제안은 다음 날에도 뜨지 않는다. 환율 제안은 확인 버튼 없이 "알겠어요"로 끝낼 수 있고 그날은 다시 뜨지 않는다.
- AC8. 환율, 교통패스, 입장권 제안이 함께 맞아도 섬은 하나만 보인다. 순서는 교통패스, 공항 교통권, 입장권(장소 순), 할인권, 환율이다. 출발 전날 저녁 안내가 맞으면 저녁 안내가 먼저 뜬다. 여행 중에는 이 제안들이 뜨지 않는다.

## 확정된 제약과 근거

- 환율 안내는 수치 옆에 부드러운 한 줄 판단을 붙이되, 모든 안내에 "참고용이에요. 환전은 은행이나 앱에서 직접 해 주세요."를 붙이고 환전을 실행하는 화면은 만들지 않는다. 판단 없이 수치만 보이면 친구처럼 챙겨 주는 느낌이 약하고, 판단만 하면 투자 조언처럼 들리기 때문이다(사용자 확정, 2026-11-19).
- 판단 기준은 현재 환율과 최근 30일 평균의 차이이고, ±2%를 경계로 세 가지 문구를 쓴다. 안내 문구는 LLM이 아니라 규칙으로 만든다([llm-integration](../../decisions/llm-integration.md)).
- 환율 출처는 Frankfurter API(유럽중앙은행 기준환율)다. 키가 필요 없고, 엔→원 최신값과 기간별 기록을 모두 받을 수 있음을 2026-11-19에 직접 호출로 확인했다. 영업일 하루 한 번 갱신되는 기준환율이라 은행의 실제 환전 환율, 수수료와 다르다.
- 원화는 보여 주기만 하고 저장하지 않는다. 입력과 계산의 기준은 엔이다(사용자 확정, 2026-11-19). 원화로 예산을 정하는 기능은 이번에 만들지 않는다.
- 구매 제안은 출발 14일 전부터 띄운다. 인기 입장권은 몇 주 전에 매진되기도 해서 2주 전이 부담 없이 알리기 좋은 때다(사용자 확정, 2026-11-19).
- 마이리얼트립 링크는 교통권, 패스권, 입장권, 할인권을 추천하는 데만 쓰고, 환율이나 환전과는 연결하지 않는다. 직접 사지 않고 검색 결과로 넘기는 데까지만 한다. 검색어는 "오사카 교통패스", "오사카 공항 교통권", "<장소> 입장권", "오사카 할인 쿠폰"으로 정해 둔 기본값이다(사용자 확정, 2026-11-19).

## 가정 (바꿀 수 있음)

- 환율 제안과 구매 제안은 여행 화면에서만 뜬다. 일차 화면에서는 여행 중 제안만 뜬다.
- 환율은 서버에서 받아 하루 동안 쓴다. 한 사용자가 화면을 열 때마다 새로 받지 않는다.
- 마이리얼트립 검색 주소는 `https://www.myrealtrip.com/search?query=<검색어>` 형태다. 2026-11-19에 이 형태가 검색 결과 페이지로 열리는 것을 확인했다. 제휴 코드나 추적 값은 붙이지 않는다.
- 공항 교통권과 할인권은 서류 칸이나 체크리스트와 연결되지 않아서 완료를 알 수 없다. 사용자가 확인하거나 "나중에"를 누를 때까지 하루에 한 번 뜨고, 확인하면 끝난다.
- 입장권이 필요한 장소는 위 일곱 곳으로 정해 둔 이름 목록이다. AI 코스가 이름을 다르게 적으면 제안이 뜨지 않을 수 있다.
- 환율 제안의 환산액 표기는 "100엔 = N원"이다.
- 원화 환산은 `≈`와 함께 옅은 작은 글씨로, 화면의 주된 금액(엔)보다 눈에 띄지 않게 둔다.
- 출발 전 제안은 사용자(계정)마다 따로 처리 기록을 쓴다.

## 범위 밖과 이유

- 원화로 예산이나 여비를 입력하기 — 엔 기준 계산이 날마다 달라진다. 필요하다는 근거가 나오면 다시 정한다.
- 환전 실행, 환전소·은행 연결, 환전 수수료 비교 — `PRODUCT.md`의 구매 경계와 투자 조언 위험 때문에 다루지 않는다.
- 숙소, 와이파이·유심, 여행자 보험의 추천 — 언제가 필요한 순간인지 정해지지 않았다.
- 검색어 직접 고치기와 상품 추천(특정 상품 링크) — 검색 결과로 넘기는 것까지만 한다.
- 가격 비교, 가격 알림 — 가격 정보를 받아 오지 않는다.
- 여행 중 환율 제안 — 출발 전 준비에 한한다.

## 미룬 결정

- 원화로 예산 정하기: 이 사양을 쓴 뒤 사용자가 엔 기준 입력이 불편하다고 할 때 다시 다룬다.
- 환율 판단 기준 조정(30일 평균, ±2%): 실제로 써 보고 문구가 맞지 않다고 할 때 다시 다룬다. 그때까지는 이 값을 쓴다(임시).

## 남은 위험

- 기준환율은 은행의 실제 환율과 달라서, 환율 제안의 "괜찮은 편이에요"가 실제 체감과 어긋날 수 있다. 참고 안내를 모든 안내에 붙여 막는다.
- 마이리얼트립 검색 주소 형태가 바뀌면 링크가 기대한 검색 결과를 보여 주지 않을 수 있다. 사이트가 바뀌면 이 사양의 주소를 고친다.
- Frankfurter가 중단되거나 속도가 느려지면 원화 환산과 환율 제안이 사라진다. 조용히 생략하므로 다른 기능은 영향이 없다.
- 입장권이 필요한 장소 목록이 일곱 곳뿐이라, 다른 명소의 입장권은 제안되지 않는다.
