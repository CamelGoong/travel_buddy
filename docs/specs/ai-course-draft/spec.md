# AI 코스 초안: 동행 유형과 취향에 맞춘 코스와 체크리스트 제안

여행을 만들 때 동행 유형과 취향을 고르면 서비스가 LLM으로 일차별 코스 초안을 짜고, 체크리스트에 더하면 좋을 항목을 "이거 필요해?" 하고 제안한다. LLM이 실패하면 지금의 고정 명소 목록으로 조용히 대체해서, 여행 만들기는 끊기지 않는다. [osaka-first-trip-loop](../osaka-first-trip-loop/spec.md)의 미룬 결정 "AI 코스 생성"을 해소하는 작업 단위다.

연결된 근거:
- [PRODUCT.md](../../../PRODUCT.md) — 제품 전제. 이 작업에는 "모든 제안은 사용자가 확인해야 실행된다", "직접 구매하지 않는다", "코스 추천은 유명 명소 중심의 가벼운 초안까지", "말투와 경험을 2030에 맞춘다"가 적용된다.
- [llm-integration](../../decisions/llm-integration.md) — LLM을 쓰는 곳과 쓰지 않는 곳, 공급자와 모델, 서버 호출, 키 관리, 실패 시 대체, 비용 상한. 이 스펙은 그 규칙을 다시 적지 않는다.
- [data-storage](../../decisions/data-storage.md) — 계정에 묶어 Supabase에 저장하는 규칙.
- [osaka-contextual-suggestions](../osaka-contextual-suggestions/spec.md) — 아침·저녁 안내와 다음 장소 길찾기, 주변 명소가 코스의 장소와 좌표를 읽는다. 이 스펙은 그 제안이 AI 코스에서도 동작하게 하는 데까지만 다룬다.
- [route-line](../../decisions/route-line.md) — 노선도가 일차의 장소와 예정 시각으로 진행을 보여 주는 규칙.
- [ui-composition](../../decisions/ui-composition.md) — 일반 UI 구성과 상태 표현 규칙. 화면 작업은 `DESIGN.md`부터 읽는다.
- [GLOSSARY.md](../../../GLOSSARY.md) — 여행, 일차, 코스 초안, 기본 코스, 동행 유형, 취향, 체크리스트, 체크리스트 제안, 예정 시각의 뜻.

## 사용자에게 보이는 결과

1. 여행 만들기 화면에서 시작일·종료일과 함께 동행 유형 하나(혼자, 친구, 연인, 가족·아이, 부모님)와 취향을 최대 세 개(맛집, 쇼핑, 역사·문화, 테마파크, 야경, 카페) 고를 수 있다. 둘 다 고르지 않아도 된다.
2. 여행 만들기를 누르면 "코스 짜는 중…"이 보이고, 잠시 뒤 기간의 모든 일차가 장소(이름과 지도 좌표)와 예정 시각으로 채워진 코스 초안이 보인다. 고른 동행 유형과 취향이 장소 구성에 드러난다.
3. 코스를 만들지 못했으면 여행은 그대로 만들어지고, 지금과 같은 기본 코스가 보인다. 코스 초안에는 "기본 코스"라는 작은 표시가 붙는다.
4. 체크리스트 아래에 "이거 필요해?" 제안이 최대 세 개 보인다. "추가"를 누르면 그 항목이 체크리스트에 미완료로 들어가고, "괜찮아요"를 누르면 제안이 사라진다.
5. 여행 화면, 일차 화면, 아침 안내, 저녁 안내, 노선도가 모두 같은 코스를 보여 준다. 새로고침하거나 다시 로그인해도 코스와 제안 처리 결과가 그대로다.

## 승인된 범위

- 여행 만들기에 동행 유형과 취향 선택 추가
- 여행을 만들 때 LLM으로 코스 초안 생성, 결과를 여행에 묶어 저장
- 여행을 만들 때 LLM으로 체크리스트 제안 생성과 "추가/괜찮아요" 처리
- 생성 실패 시 기본 코스와 제안 없음으로 대체, "기본 코스" 표시
- 저장된 코스를 여행 화면, 일차 화면, 아침·저녁 안내, 노선도가 함께 쓰기
- 사용자당 하루 생성 횟수 제한

## 수용 기준

AC1–AC9는 실행 중인 앱에서 실제 브라우저로 확인한다. LLM 응답이 필요한 기준은 실제 Gemini 호출로 한 번 이상 확인하고, 실패 경로는 호출을 실패시키는 방법(잘못된 키, 제한 시간 등)으로 확인한다.

- AC1. 여행 만들기 화면에 동행 유형 다섯 개 중 하나와 취향 여섯 개 중 최대 세 개를 고를 수 있다. 네 번째 취향은 고를 수 없다. 아무것도 고르지 않아도 여행이 만들어진다.
- AC2. 4박 5일 여행을 만들면 1일차부터 5일차까지 모든 일차에 장소가 한 곳 이상 있고, 장소마다 예정 시각이 있으며, 한 일차 안의 예정 시각은 이른 순서다. 같은 장소가 두 일차에 겹치지 않는다. 8일 이상 여행도 모든 일차가 채워진다.
- AC3. AC2의 여행을 새로고침하고, 로그아웃 후 다시 로그인해도 같은 코스(같은 장소, 같은 예정 시각)가 보인다.
- AC4. 오늘이 여행 일차일 때 아침 안내의 장소 목록, 일차 화면의 장소 목록, 노선도의 장소 정류장이 저장된 AI 코스의 그날 장소와 같다. 저녁 안내의 내일 장소 요약도 저장된 코스를 따른다.
- AC4-1. AI 코스에서도 다음 장소 길찾기 제안이 뜨고, 확인하면 그 장소의 좌표로 길찾기가 열린다. 모든 장소에 좌표가 있고, 좌표가 오사카와 근교 범위 밖이거나 비어 있는 코스는 쓰지 않고 기본 코스로 대체한다(AC5와 같은 대체).
- AC5. LLM 호출이 실패하면(오류, 제한 시간 초과, 한도 초과, 형태가 맞지 않는 응답) 여행은 만들어지고, 코스 초안은 기본 코스와 같으며 "기본 코스" 표시가 보인다. 체크리스트에는 기본 다섯 항목만 있고 제안은 없다. 오류 화면은 보이지 않는다.
- AC6. 같은 사용자가 오사카 날짜 기준 하루에 여섯 번째로 여행을 만들면 LLM을 부르지 않고 기본 코스로 만들어진다.
- AC7. AI 코스로 만든 여행의 체크리스트 아래에 제안이 1–3개 보인다. 제안 하나에 "추가"를 누르면 체크리스트 맨 아래에 미완료로 들어가고 제안 목록에서 사라진다. 다른 제안에 "괜찮아요"를 누르면 사라지고, 새로고침해도 다시 보이지 않는다.
- AC8. 추가한 제안 항목은 기본 항목처럼 완료 표시를 할 수 있고, 1일차 전날 저녁 안내의 준비 항목에도 미완료 항목으로 함께 보인다.
- AC9. 이 기능 전에 만든 여행은 지금처럼 기본 코스를 보여 주고, "기본 코스" 표시가 붙는다.

LLM 출력 품질은 실행마다 달라지므로 eval로 증명한다. eval 케이스는 구현 중 프롬프트를 다듬는 데 쓰지 않은 별도 케이스로 둔다.

- AC10. 장소 실재성
  - 지표: 생성된 코스 가운데, 모든 장소가 오사카와 당일치기 근교(교토·나라·고베 포함)에 실제로 있고 현재 운영 중인 관광지·상점가·음식 거리인 코스의 비율
  - 목표: 보류 케이스 10개 중 9개 이상. 장소마다 좌표가 이름의 실제 위치에서 500m 안인지도 함께 판정한다.
  - 케이스 출처: 기간(1일, 3일, 5일, 8일, 14일) × 동행 유형 × 취향 조합에서 고른 10개. 이 스펙 폴더에 케이스 목록으로 둔다.
- AC11. 조건 반영
  - 지표: 고른 동행 유형과 취향이 장소 구성에 드러난다고 판정된 코스의 비율(예: 가족·아이에 심야 술집 위주가 아님, 테마파크 취향에 테마파크 포함)
  - 목표: AC10과 같은 보류 케이스 10개 중 8개 이상
  - 케이스 출처: AC10과 같다.

## 확정된 제약과 근거

- LLM 사용 범위, 공급자, 서버 호출, 키, 실패 시 대체, 비용 상한은 [llm-integration](../../decisions/llm-integration.md)을 따른다.
- 입력은 날짜, 동행 유형 하나, 취향 최대 세 개다. 한 줄 자유 입력은 받지 않는다. 몇 번의 탭으로 끝나야 하고 결과를 확인하기 쉬워야 하기 때문이다. (사용자 확정, 2026-11-19)
- 장소는 LLM이 자유롭게 고른다. 미리 정해 둔 명소 목록으로 제한하지 않는다. 더 다양하고 동적인 코스를 원했기 때문이다. 대신 없는 장소가 나올 위험은 AC10의 eval로 관리한다. (사용자 확정, 2026-11-19)
- 체크리스트 제안은 사용자가 "추가"를 누른 것만 체크리스트에 들어간다. 바로 넣지 않는다. "모든 제안은 사용자가 확인해야 실행된다"는 제품 원칙 때문이다. (사용자 확정, 2026-11-19)
- 코스는 여행을 만들 때 한 번만 생성해 여행에 묶어 저장한다. 화면을 열 때 다시 생성하지 않는다. 생성 결과가 매번 달라지므로, 저장하지 않으면 새로고침할 때마다 코스가 바뀐다.
- 기본 코스로 대체되었는지와 그 이유(호출 실패, 한도 초과, 형태 오류, 앱의 하루 제한)를 여행마다 기록한다. 화면의 "기본 코스" 표시와, 유료 모델로 옮길지 판단하는 데 쓴다.
- 구매는 하지 않는다. 제안 항목이 입장권이나 패스여도 체크리스트 항목일 뿐, 구매 화면이나 마이리얼트립으로 연결하지 않는다.

## 가정 (바꿀 수 있음)

- 장소마다 위도·경도를 함께 받는다. 길찾기와 도착 감지가 좌표를 쓰기 때문이다. 좌표는 LLM이 알려 주는 값이라 틀릴 수 있다.
- 장소 이름은 한국어로, 한국 여행자에게 익숙한 표기로 받는다.
- 예정 시각은 오사카 현지 시각 07:00–22:00 사이로 받는다. 1일차와 마지막 일차는 이동을 고려해 장소를 적게 잡도록 요청한다.
- 일차마다 장소는 2–5곳으로 요청한다.
- 동행 유형과 취향은 여행에 함께 저장하지만, 이번에는 만들 때만 쓰고 다른 화면에 보여 주지 않는다.
- 하루 제한 5회는 오사카 날짜 기준으로 센다. 바꾸기 쉬운 기본값이다.
- 체크리스트 제안 항목 이름은 짧은 명사구(최대 20자)로 받는다. 기본 다섯 항목과 같은 뜻의 제안은 보여 주지 않는다.
- "기본 코스" 표시는 코스 초안 제목 옆의 작은 배지로 둔다. 시각 표현은 `DESIGN.md`와 [ui-composition](../../decisions/ui-composition.md)을 따른다. 화면 구성이 기존 패턴(선택 칩, 목록, 배지, 버튼)의 조합이라 시제품 비교는 생략했다.
- "코스 짜는 중…" 상태는 기존 여행 만들기 버튼의 대기 표시를 그대로 쓴다.

## 범위 밖과 이유

- 코스 "다시 짜 줘" 재생성 — 호출 횟수와 비용 상한을 다시 정해야 한다. [llm-integration](../../decisions/llm-integration.md)이 허용하지 않는다.
- 장소 추가·수정·삭제와 예정 시각 변경 — [osaka-first-trip-loop](../osaka-first-trip-loop/spec.md)의 미룬 결정과 같은 시점에 다룬다.
- 오사카가 아닌 도시 — 대체용 기본 코스가 오사카뿐이다.
- 제안 항목의 구매 연결(마이리얼트립) — 구매 추천 알림의 동작이 아직 정해지지 않았다.
- 아침·저녁 안내 문구, 옷차림, 준비 항목 규칙의 LLM화 — [llm-integration](../../decisions/llm-integration.md)이 규칙으로 두기로 했다.
- 배포 — 로컬에서 실행해 확인한다.

## 미룬 결정

- 코스 재생성: 이 스펙이 기본 브랜치에 들어가 사용자가 AI 코스를 직접 써 본 뒤, 다음 작업 단위를 고를 때 다시 다룬다. 그때까지는 만들 때 한 번만 생성한다.
- 동행 유형·취향을 여행을 만든 뒤 바꾸기: 위와 같은 시점에 다룬다. 그때까지는 만들 때만 고른다.

## 남은 위험

- Gemini 무료 한도는 프로젝트마다 다르고 공개된 고정 값이 없다. 한도가 작으면 기본 코스로 대체되는 일이 잦을 수 있다. 사용자 흐름은 끊기지 않지만 AI 코스를 보기 어려워진다.
- LLM이 알려 준 좌표가 이름과 다른 곳을 가리킬 수 있다. 범위 검사로 걸러지는 것은 오사카 밖 좌표뿐이라, 범위 안의 엉뚱한 좌표는 길찾기가 다른 곳으로 안내할 수 있다. AC10에서 좌표 정확도도 함께 본다.
- LLM이 자유롭게 고르므로, eval을 통과해도 가끔 폐업했거나 이름이 어긋난 장소가 나올 수 있다. 사용자가 장소를 고칠 수 없는 동안에는 그대로 보인다.
- 무료 등급의 입력은 Google이 제품 개선에 쓸 수 있다. 입력에는 날짜, 동행 유형, 취향만 들어가고 이메일 같은 개인 정보는 넣지 않는다.
- 생성에 수 초가 걸려 여행 만들기 버튼의 대기 시간이 길어진다. 제한 시간을 넘으면 기본 코스로 넘어간다.

## Setup before implementation

- Google AI Studio의 Gemini API 키 — 서버에서 코스와 제안을 생성하는 데 쓴다. 완료 조건: 앱 밖에서 그 키로 Gemini API에 짧은 텍스트 생성 요청을 보내 정상 응답을 받는다. 결제 수단은 연결하지 않는다.

## Post-release check
