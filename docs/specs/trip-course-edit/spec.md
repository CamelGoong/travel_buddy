# 코스 편집: 순서·시각 바꾸기, 장소 추가·삭제, AI로 다시 짜기

여행의 코스 초안은 서비스가 짜 준 그대로 굳어 있지 않고, 주인이 일차 안에서 순서와 예정 시각을 바꾸고, 장소를 지우거나 더하고, 마음에 안 들면 AI로 코스 전체를 다시 짤 수 있다. 장소는 정해 둔 오사카 명소 목록에서 고르거나 직접 이름을 입력해 더한다. [osaka-first-trip-loop](../osaka-first-trip-loop/spec.md)과 [ai-course-draft](../ai-course-draft/spec.md)가 미룬 "장소 추가·수정·삭제와 예정 시각 변경", "코스 재생성"을 해소한다.

연결된 근거:
- [PRODUCT.md](../../../PRODUCT.md) — 제품 전제. 이 작업에는 "코스 추천은 유명 명소 중심의 가벼운 초안까지만 한다. 세밀한 일정은 사용자가 정한다", "모든 제안은 사용자가 확인해야 실행된다"가 적용된다.
- [llm-integration](../../decisions/llm-integration.md) — AI로 다시 짜기는 이 결정이 막아 둔 "코스 재생성"을 연다. 이 작업이 그 결정의 경계를 함께 고치고, 호출 위치, 키, 실패 시 동작, 하루 5회 제한은 그대로 따른다.
- [route-line](../../decisions/route-line.md) — 편집한 코스로 노선도의 장소 정류장이 바뀐다.
- [ui-composition](../../decisions/ui-composition.md) — 편집 버튼, 입력, 확인 창, 선택은 공식 shadcn 구성을 쓴다. 화면 작업은 `DESIGN.md`부터 읽는다.
- [trip-documents](../trip-documents/spec.md) — 입장권 서류 파일은 코스의 장소 이름에 연결되어 있다. 장소를 지우거나 코스를 다시 짜면 그 연결이 풀린다.
- [osaka-contextual-suggestions](../osaka-contextual-suggestions/spec.md) — 길찾기, 도착 감지, 주변 명소가 코스의 장소와 좌표를 읽는다. 좌표 없는 장소의 동작은 이 스펙이 정한다.
- [GLOSSARY.md](../../../GLOSSARY.md) — 코스 초안, 기본 코스, 일차, 예정 시각, 주변 명소, 노선도의 뜻. 이 작업이 직접 입력 장소를 더한다.

## 사용자에게 보이는 결과

1. 일차 화면과 여행 화면의 코스 초안에서 "편집"을 누르면 편집 모드가 되고, 장소마다 위·아래 버튼, 시각 입력, 삭제 버튼이 보이고, 일차 맨 아래에 "장소 추가"가 보인다.
2. 위·아래 버튼을 누르면 바로 위나 아래 장소와 자리가 바뀐다. 예정 시각은 자리에 남고 장소 이름만 바뀐다. 시각을 직접 고치면 일차 안에서 시각 순서대로 다시 정렬된다.
3. 장소를 지우면 그 자리가 사라진다. 장소가 모두 없는 일차는 "자유 일정"으로 보인다.
4. "장소 추가"에서 정해 둔 오사카 명소 목록에서 고르거나, 가고 싶은 곳 이름을 직접 입력해 더한다. 새 장소의 기본 예정 시각은 그날 마지막 장소의 2시간 뒤(22:00을 넘으면 22:00)이고 고칠 수 있다.
5. 직접 입력한 장소는 코스와 노선도에 똑같이 보이고, 길찾기를 누르면 지도 앱이 그 이름을 검색해 연다. 도착 감지와 "지금 위치에서 몇 분" 안내는 이 장소에서만 생략된다.
6. 코스 화면의 "AI로 다시 짜기"를 누르면 "직접 고친 내용이 사라져요" 확인 창이 뜨고, 확인하면 같은 동행 유형과 취향으로 코스 전체가 새로 만들어진다. 한도를 넘었거나 AI가 실패하면 지금 코스가 그대로 남고 "지금은 다시 짜지 못했어요"가 보인다.
7. 동반자 화면에는 편집과 다시 짜기가 보이지 않는다. 주인만 한다.

## 승인된 범위

- 일차 안의 장소 순서 바꾸기(위·아래), 예정 시각 바꾸기와 자동 정렬
- 장소 삭제, 장소 추가(정해 둔 명소 목록에서 고르기, 직접 이름 입력)
- 직접 입력한 장소의 좌표 없는 동작(이름 검색 길찾기, 도착 감지·소요 시간 생략)
- 입장권 서류 파일의 장소 연결 정리
- AI로 코스 다시 짜기(주인만, 하루 5회 제한에 포함, 실패하면 현재 코스 유지)

## 수용 기준

모두 실행 중인 앱에서 실제 브라우저로 확인한다. AI로 다시 짜기는 실제 Gemini 호출로 한 번 이상 확인하고, 실패 경로는 호출을 실패시키는 방법(잘못된 키, 한도 초과 등)으로 확인한다.

- AC1. 1일차에서 두 번째 장소의 위 버튼을 누르면 첫 번째와 자리가 바뀐다. 두 자리의 예정 시각(예: 10:00, 12:30)은 그대로이고 장소 이름만 바뀐다. 첫 번째 장소의 위 버튼과 마지막 장소의 아래 버튼은 눌리지 않는다. 새로고침해도 바뀐 순서가 그대로다.
- AC2. 장소의 예정 시각을 15:00에서 11:00으로 고치면 그 일차 안에서 시각 순서대로 자리가 다시 정렬된다. `07:00`–`22:00` 밖이거나 `HH:MM` 형식이 아니면 바뀌지 않고 이유가 보인다.
- AC3. 장소를 지우면 일차에서 사라지고, 모두 지우면 그 일차가 "자유 일정"으로 보인다. 자유 일정인 일차에도 장소를 추가할 수 있다.
- AC4. "장소 추가"에서 정해 둔 명소 목록(주변 명소의 목록)에서 하나를 고르면 그 장소가 이름과 좌표와 함께 일차 맨 아래에 기본 시각으로 추가된다. 같은 일차에 이미 있는 장소는 다시 추가되지 않고 이유가 보인다. 일차당 장소는 최대 8곳이고, 넘으면 추가되지 않고 이유가 보인다.
- AC5. 직접 이름을 입력하고 "위치 없이 이름만 추가"하면(1–30자, 위치를 찾아 더하는 흐름은 [day-route-map](../day-route-map/spec.md)) 그 이름의 장소가 좌표 없이 추가된다. 이름이 비어 있거나 30자를 넘으면 추가되지 않고 이유가 보인다. 이 장소의 다음 장소 길찾기를 누르면 지도 앱이 장소 이름을 검색해 열린다. 이 장소 근처에서는 도착 감지와 소요 시간 안내가 나오지 않고, 다른 장소의 안내는 그대로다.
- AC6. 편집한 코스가 여행 화면, 일차 화면, 아침 안내, 저녁 안내, 노선도에 모두 똑같이 보이고, 새로고침하거나 다시 로그인해도 그대로다. 이 편집은 기본 코스 여행에도 같은 방식으로 동작하고 "기본 코스" 표시는 그대로다.
- AC7. 입장권 파일이 연결된 장소를 지우면 그 파일의 연결이 풀려 서류 보관함에서 "장소 없음"으로 보이고, 그 장소 근처에서 입장권 섬이 뜨지 않는다. 같은 이름의 장소를 다시 추가해도 연결은 되살아나지 않는다.
- AC8. "AI로 다시 짜기"를 누르면 확인 창이 뜨고, 취소하면 코스가 그대로다. 확인하면 모든 일차가 새 장소와 예정 시각으로 채워지고(AI 코스 사양의 AC2와 같은 기준), 직접 입력한 장소와 이전 편집은 사라지고, 새 코스에 없는 장소에 연결된 입장권 파일은 "장소 없음"이 된다.
- AC9. AC8을 하루에 다섯 번(여행 만들기와 합쳐 오사카 날짜 기준) 쓴 뒤 여섯 번째로 누르면 AI를 부르지 않고 "오늘은 더 다시 짤 수 없어요"가 보이고 코스가 그대로다. AI 호출이 실패하는 상황(잘못된 키, 제한 시간 초과)에서도 코스가 그대로이고, 기본 코스로 바뀌지 않으며, 오류 화면은 보이지 않는다.
- AC10. 동반자 계정 화면에는 편집, 장소 추가, AI로 다시 짜기가 보이지 않고, 같은 일을 하는 요청을 직접 보내도 거절된다.

## 확정된 제약과 근거

- 장소 추가는 미리 정한 명소 목록에서 고르는 방법과 직접 이름을 입력하는 방법 둘 다 제공한다. 직접 입력한 장소는 좌표가 없다. 지도 검색 서비스는 키와 비용 설정이 필요하고 "세밀한 일정은 사용자가 정한다"는 제품 경계에 이름 입력으로 충분하기 때문이다(사용자 확정, 2026-11-19).
- 순서를 바꿀 때 예정 시각은 자리에 남고 장소만 옮긴다. 시각을 고치면 일차 안에서 시각 순서로 자동 정렬한다. 일차 안의 예정 시각은 항상 이른 순서라는 규칙을 길찾기와 노선도가 쓰므로 깨지지 않게 하기 위해서다(사용자 확정, 2026-11-19).
- AI로 다시 짜기를 허용한다. 기존 하루 5회 제한 안에서만 하고, 실패하면 현재 코스를 유지한다. 코스 재생성을 막아 두었던 [llm-integration](../../decisions/llm-integration.md)의 경계를 이 작업에서 고친다. 비용 상한(무료 등급, 하루 5회)이 이미 있고 편집만으로는 마음에 안 드는 코스를 통째로 바꾸기 번거롭기 때문이다(사용자 확정, 2026-11-19).
- 편집과 다시 짜기는 주인만 한다([trip-companions](../trip-companions/spec.md)의 권한 결정). 여행에 동반자가 없는 동안에는 여행을 만든 계정이 곧 주인이다.
- 다른 일차로 장소 옮기기는 이번에 만들지 않는다(사용자 확정, 2026-11-19).

## 가정 (바꿀 수 있음)

- 위·아래 버튼으로 옮긴다. 끌어 놓기는 휴대폰에서 스크롤과 겹쳐 쓰기 불편해서 쓰지 않는다.
- 편집 모드는 화면 안에서 "편집"과 "완료"로 켜고 끈다. 편집은 바로 저장되고 별도의 저장 버튼은 없다.
- 직접 입력한 장소 이름은 앞뒤 공백을 지우고, 같은 일차 안의 이름이 같은 장소는 추가하지 않는다.
- 같은 장소가 다른 일차에 겹치는 것은 막지 않는다. AI 코스 생성 기준(겹치지 않기)은 생성에만 적용한다.
- 직접 입력한 장소의 길찾기 검색어는 "<장소 이름> 오사카"다.
- AI로 다시 짤 때 동행 유형과 취향은 여행을 만들 때 저장한 값을 쓴다.
- 편집한 코스가 기본 코스 여행이면 그 코스는 계속 기본 코스로 표시한다. AI로 다시 짜서 성공하면 "기본 코스" 표시는 사라진다.
- 화면 시안은 만들지 않았다. 기존 패턴(목록, 버튼, 입력, 선택, 확인 창)의 조합이기 때문이다. 써 보고 어색하면 그때 고친다.

## 범위 밖과 이유

- 다른 일차로 장소 옮기기, 일차 통째로 바꾸기 — 이번에는 한 일차 안에서만 편집한다.
- 끌어 놓기로 순서 바꾸기 — 휴대폰에서 쓰기 불편하다.
- 지도 검색으로 장소 고르기(좌표를 가진 자유 검색) — 지도 서비스의 키와 비용 설정이 필요하다.
- 직접 입력한 장소의 좌표 지정, 도착 감지 — 좌표를 얻는 방법이 없다.
- 장소별 메모, 소요 시간 편집, 이동 수단 지정 — 코스 초안은 가벼운 초안까지만 다룬다.
- 다시 짜기 결과 되돌리기, 다시 짜기 이력 — 한 번 바꾸면 이전 코스는 남기지 않는다.
- 오사카가 아닌 도시 — 대체용 기본 코스와 명소 목록이 오사카뿐이다.

## 미룬 결정

- 다른 일차로 장소 옮기기: 사용자가 이 편집을 써 보고 필요하다고 할 때 다시 다룬다. 그때까지는 한 일차 안에서만 편집한다(임시).
- 직접 입력한 장소에 좌표 붙이기: 지도 검색 서비스를 붙일 때 다시 다룬다. 그때까지는 이름 검색 길찾기만 쓴다(임시).

## 남은 위험

- 좌표 없는 장소가 늘면 도착 감지와 소요 시간 안내가 줄어, 제안이 덜 정확한 코스가 된다.
- AI로 다시 짜기가 직접 고친 내용을 모두 덮어쓴다. 확인 창으로 알리지만 실수로 눌러 잃을 수 있다.
- 입장권 파일의 장소 연결은 이름 일치로 하므로, 같은 장소를 지웠다 다시 추가해도 연결은 되살아나지 않는다.
- 하루 5회에는 여행 만들기와 다시 짜기가 함께 들어가서, 여행을 여러 번 만들면 다시 짜기가 막힐 수 있다.
