# 파스텔 글래스 테마: 앱 전체를 밝고 투명한 2030 감각으로 바꾸기

앱의 색, 면의 투명도, 모양, 글꼴을 [visual-theme](../../decisions/visual-theme.md)이 정한 파스텔 글래스로 바꾼다. 복숭아·연보라·하늘색이 번지는 밝은 배경 위에 반투명 카드와 제안 섬이 떠 있고, 글자는 또렷하다. 기능과 화면 구성은 그대로이고 겉모습만 바뀐다. 이전에 "시각 테마는 나중에 설계한다"로 미뤄 둔 작업을 해소한다.

연결된 근거:
- [PRODUCT.md](../../../PRODUCT.md) — "말투와 경험 전체를 촌스럽지 않게, 2030에 맞춘다".
- [visual-theme](../../decisions/visual-theme.md) — 방향, 면의 투명도, 대비 기준, 색, 글꼴을 정한 결정. 이 스펙은 그 규칙을 다시 적지 않고, 모든 화면에 적용되었는지를 기준으로 삼는다.
- [ui-composition](../../decisions/ui-composition.md) — 일반 UI는 공식 shadcn 구성과 의미 토큰을 쓴다. 이 테마도 토큰을 바꾸는 방식으로 적용하고 화면마다 임의의 색을 쓰지 않는다.
- [suggestion-nudge](../../decisions/suggestion-nudge.md) — 제안 섬의 그라데이션·반투명 규칙은 이 테마와 같은 방향이라 그대로 따른다.
- [route-line](../../decisions/route-line.md) — 노선도의 구성은 그대로이고 색과 면만 이 테마를 따른다.
- `DESIGN.md` — 값 표와 컴포넌트 목록이 이 작업으로 바뀌므로 함께 갱신한다. 화면 작업은 `DESIGN.md`부터 읽는다.

## 사용자에게 보이는 결과

1. 모든 화면의 배경이 복숭아에서 연보라, 하늘색으로 번지는 밝은 그라데이션이고, 핑크와 하늘색의 흐릿한 빛이 비친다.
2. 카드, 제안 섬, 노선도, 입력, 확인 창이 반투명 유리처럼 보이고 뒤의 배경이 은은하게 비친다.
3. 모든 글자가 또렷하다. 카드 위 본문과 라벨은 투명한 면 위에서도 읽기 쉽다.
4. 주 버튼이 보라에서 하늘색으로 번지는 알약 모양이고, 카드와 칩은 아주 둥글다.
5. 글꼴이 한글 산세리프로 바뀌고, 제목은 굵게 보인다.

## 승인된 범위

- 전체 색 토큰, 배경, 면의 투명도와 흐림, 모양(반지름), 글꼴 교체
- 이 앱의 모든 화면(로그인, 내 여행, 여행 만들기, 여행, 일차, 서류 보관함, 오프라인 서류 등)과 제안 섬, 노선도에 적용
- `DESIGN.md` 값 갱신

## 수용 기준

실행 중인 앱에서 실제 브라우저로 확인한다. 휴대폰 폭(390px)과 데스크톱 폭에서 모두 본다.

- AC1. 로그인, 내 여행, 여행 만들기, 여행, 일차, 서류 보관함, 오프라인 서류 화면이 모두 같은 그라데이션 배경과 반투명 카드를 쓴다. 한 화면도 이전의 흰 단색 배경이나 단색 카드로 남아 있지 않다.
- AC2. 카드와 제안 섬은 `backdrop-filter` 흐림이 적용되어 있고, 카드 가장자리에 흰 테두리가 있다. 배경의 색 덩어리가 카드 뒤로 비쳐 보인다.
- AC3. 카드 위 본문 글자와 배경(카드 뒤가 가장 밝은 곳과 가장 어두운 곳 두 지점) 사이 명도 대비가 모두 4.5:1 이상이다. 제안 섬, 입력, 버튼 글자도 같다.
- AC4. 주 버튼은 보라에서 하늘색 그라데이션 알약이고, 비활성 상태와 포커스 상태가 보인다. 체크박스, 입력, 배지, 확인 창이 같은 테마 색을 쓴다.
- AC5. 본문과 제목 글꼴이 한글 산세리프이고(세리프와 고정폭 제목은 쓰지 않는다), 제목은 굵기 800이다. 한글, 숫자, 영문이 모두 같은 글꼴로 보이고 대체 글꼴로 깨지지 않는다.
- AC6. 휴대폰 폭에서 가로 스크롤이 생기지 않고, 여행 화면의 날짜 줄과 "내 여행"·로그아웃 버튼이 겹치지 않는다.
- AC7. 이 작업 전후로 모든 기능이 그대로 동작한다. 체크리스트, 여비 기록, 서류 올리기, 제안 섬, 로그인이 모두 화면 변경 없이 같은 결과를 낸다.
- AC8. 모션 줄이기 설정에서도 모든 화면이 읽을 수 있고, 투명 효과를 지원하지 않는 환경에서도 카드가 불투명한 흰색 면으로 읽을 수 있다.

## 확정된 제약과 근거

- 방향은 [visual-theme](../../decisions/visual-theme.md)의 파스텔 글래스이고, 어두운 테마는 만들지 않는다(사용자 확정, 2026-11-19).
- 글자는 또렷해야 한다. 투명도가 글자 대비를 해치면 투명도를 올린다(사용자 확정, 2026-11-19).
- 기능과 화면 구성은 바꾸지 않는다. 겉모습만 바꾼다.

## 가정 (바꿀 수 있음)

- 글꼴은 Noto Sans KR(next/font로 불러옴)로 한다. 한글 웹폰트 중 가장 안정적으로 쓸 수 있어서이고, 시안의 시스템 글꼴(맑은 고딕, Apple SD Gothic Neo)과 모양이 조금 다를 수 있다.
- 배경의 색 덩어리 위치와 색은 시안(핑크 `#ff9ec4`, 하늘색 `#8ab4ff`, 흐림 60–70px)을 기준으로 시작하고, 화면에서 보고 조정한다.
- 휴대폰이 흐림 효과를 지원하지 않거나 느리면 불투명한 흰 카드로 대신 보인다.
- 지금 앱이 쓰는 어두운 색 토큰은 그대로 두되, 앱이 어두운 테마로 바뀌는 경로는 지금도 없다.
- 로그인 화면도 같은 배경과 카드를 쓴다.

## 범위 밖과 이유

- 어두운 테마 — 이번 결정에 포함되지 않는다.
- 로고, 아이콘 모음, 일러스트, 사진 — 이번에는 색과 면과 글꼴만 바꾼다.
- 화면 구성, 문구, 제안 규칙의 변경 — 각 기능 사양이 정한다.
- 애니메이션과 전환 효과 추가 — 기존 제안 섬과 로딩 화면의 움직임만 둔다.

## 미룬 결정

- 어두운 테마: 사용자가 어두운 화면을 원한다고 할 때, 야간 글래스 시안을 다시 보고 정한다.

## 남은 위험

- 투명한 면은 밝은 야외에서 글자가 흐려 보일 수 있다. 대비 기준(4.5:1)과 [visual-theme](../../decisions/visual-theme.md)의 재검토 조건으로 관리한다.
- 흐림 효과는 저사양 휴대폰에서 스크롤을 끊어지게 할 수 있다.
- 글꼴을 바꾸면 줄바꿈과 글자 폭이 달라져 일부 화면의 줄이 넘치거나 줄어들 수 있다. 모든 화면을 두 폭에서 직접 본다.
- 이 작업은 모든 화면의 겉모습을 건드려서 다른 기능 작업과 같은 파일에서 부딪힐 수 있다. 다른 기능이 모두 들어간 뒤에 한다.
