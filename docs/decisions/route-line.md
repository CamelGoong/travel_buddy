# 노선도 진행 표시

## Decisions

- 앱 화면 맨 위에 지하철 노선도 모양의 가는 띠를 고정한다. 일직선 위에 정류장 점이 있고, 점마다 짧은 이름표가 붙는다. 지나온 구간은 선이 채워진다.
- 지금 단계의 점 하나만 은은하게 빛난다. 띠에는 지금 단계의 이름도 글자로 함께 보인다. 예를 들어 "2일차", "오사카성 천수각 · 다음 16:30"처럼 보인다.
- 여행 전체 화면에서 정류장은 "출발 전 → 1일차 → … → 마지막 일차"이고, 오늘 날짜에 해당하는 점이 빛난다.
- 일차 화면에 들어가면 띠가 한 단계 확대된다. 정류장은 그날 장소들의 예정 시각이 되고, 지금 시각에 맞는 장소가 빛난다. 지금 시각에 맞는 장소는 예정 시각이 지금 이전인 장소 가운데 가장 늦은 장소다. 사용자가 따로 누르지 않아도 저절로 옮겨 간다.

## Boundaries

- 현재 단계는 날짜와 예정 시각만으로 정한다. 위치에 따라 정하는 방식은 이 결정에 포함되지 않는다.
- 띠는 진행 상황을 보여 주기만 한다. 띠를 눌러 화면을 이동하는 동작은 이 결정이 정하지 않는다.

## Why

사용자는 따로 말하지 않아도, 쳐다보면 지금 어디쯤인지 보이기를 원했다. 상단 고정 띠, 하단 플로팅 캡슐, 목록 자체를 세로 노선으로 만드는 방식을 같은 상황(2일차 오후 2시)으로 비교했다. 그 결과 노선도 모양과 전체 단계가 가장 잘 보이는 상단 띠를 고르고, 캡슐의 장점인 지금 장소 이름 표시를 더했다. 예정 시각으로 자동 진행하는 방식은 "알아서 챙겨 주는" 경험을 위해 사용자가 직접 골랐다.

## Reconsider when

- 띠가 화면 위쪽을 차지해서 주요 내용이나 동작이 가려진다는 근거가 실제 사용에서 나올 때
- 위치 기반 제안이 들어와 현재 장소를 위치로 판단할 수 있게 될 때

## Still-rejected alternatives

- 하단 플로팅 캡슐만 쓰는 방식 — 작고 덜 거슬리지만 점에 이름표가 없어 전체 단계가 잘 보이지 않는다. 화면 위쪽 공간이 부족해지면 다시 검토한다.
- 목록 왼쪽 세로 노선 — 목록과 자연스럽게 이어지지만 스크롤과 함께 사라져서 늘 떠 있지 않는다.
- 사용자가 장소마다 "다녀왔어요"를 눌러 진행하는 방식 — 정확하지만 매번 눌러야 해서 알아서 챙겨 주는 경험과 맞지 않는다.
